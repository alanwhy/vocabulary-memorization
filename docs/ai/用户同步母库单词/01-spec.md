# 用户同步母库单词

阶段记录：Codex（GPT-6，具体子型号未提供）；2026-11-12 09:57–10:00（Asia/Shanghai）；frontend@1.23.0；规范 @sw/dev-skills@1.3.3。

## 需求陈述

用户管理页为列表中的用户增加“同步所有单词”按钮，将母库全部单词补入该用户。新增单词次数均为 1；重复单词保留用户原有次数。

## 适用范围与改动落点

这是本项目通用用户管理功能，涉及 AdminUsers、管理员路由、应用层接口及 MySQL 数据访问。只增加同步入口，已有录入和复习行为保持兼容。仓库已有同义替换模块等未提交改动，本次只追加必要改动。

## 影响面

已优先使用 CodeGraph，原始影响面输出见 [00-impact.md](00-impact.md)。AdminUsers 影响 AdminView；WordStore 接口影响应用层消费者和仓储实现。接口新增方法，现有方法不变；通过后端测试和前端构建核对兼容性。项目声明仍是模板，无实际跨客户公共层声明，本次不改变公共请求封装。

## 核心语义与数据模型

- 已确认：目标 ID 为用户列表 `u.id`，母库为 `word_dictionary`，个人词库为 `words`。
- 已确认：重复按 `(user_id, word_key)` 唯一键识别，包含已归档单词；个人 `review_count` 与母库 `occurrence_count` 是不同计数。
- 设计选择：复制母库 `word_key/display_word/senses`，新增 `review_count=1`，时间取同步时间，其他学习字段沿用新词默认值。母库计数不改变。
- 多入口：本次同步仅由管理员操作；与手工录入不同，同步不增加已有单词次数、不自动发起全库查词。
- 数据边界见下节；不使用本地持久化或 mock 存储作为真实数据来源。

## 设计要点

数据库事务内验证并锁定目标用户，再批量补齐缺词并统计该用户全部单词。唯一键冲突执行无改动更新，保留个人记录；同期重复同步串行执行。页面按用户展示同步中状态，成功后使用接口返回的单词总数更新该行。

## 边界行为清单

- 空母库/全部重复：成功，新增 0，不修改个人记录。
- 异常返回：非法 ID 为 400、用户不存在为 404、数据库错误为 500；前端显示错误并恢复按钮，事务失败回滚。提交后响应丢失可重复同步，不累计次数。
- 历史结构：复用现有表与唯一索引，无迁移；归档、释义重点和 SRS 等已有字段原样保留。
- mock/本地持久化：无新增；测试替身仅验证管理员请求契约。
- 契约：新增 `POST /api/admin/users/{id}/sync-words`，前后端由本任务一起实现，详见 [02b-design.md](02b-design.md)。
- 权限：沿用 requireAdmin；普通用户/未登录拒绝。列表每个用户均可同步，包括当前管理员及禁用账号。
- 并发/幂等：同目标用户事务锁；已有词全部跳过；与个人录入的唯一键冲突不覆盖记录。页面同步期间禁用该行的同步和删除。

## 验收标准

- [ ] 管理页每行显示“同步所有单词”，点击为该行用户同步，按钮显示同步中。
- [ ] 母库包含新词和重复词时，只补入新词，次数为 1，并复制释义；重复词保留个人次数、归档状态及学习记录。
- [ ] 再次同步新增 0；其他用户和母库计数不受影响。
- [ ] 页面更新目标单词数并显示新增数量；失败可重试，取消确认不发起请求。
- [ ] 未登录/普通用户不能调用接口；非法 ID 和不存在用户得到明确错误。
