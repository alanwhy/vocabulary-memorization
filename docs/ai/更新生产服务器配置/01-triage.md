# 迁移后发布入口仍使用旧服务器

## 复现与根因

1. 检查 `DEPLOYMENT.md`、两份 `quick-release/SKILL.md` 和 `deploy.sh` 中的生产地址。
2. 部署说明与两个发布入口仍引用迁移前地址，SSH/rsync 未指定新服务器的 7339 端口。
3. 新服务器默认 Compose 文件沿用迁移镜像配置，后端没有 `build`；只在服务器运行 `up --build` 无法构建新源码。

期望：发布入口统一使用 `root@123.56.219.4:7339`，说明源码更新流程并复用迁移后的数据卷。

## 已确认事实与核心语义

- 2026-10-08 已验证 SSH 公钥登录；部署目录为 `/root/vocabulary-memorization`。
- 后端运行正常，MySQL 为 healthy；39100 映射至容器 8080，首页返回 200，未登录 `/api/me` 返回 401。
- 服务器 `docker-compose.yml` 与 `compose.migrated.json` 内容相同，后端使用现有镜像，没有源码构建配置。
- 当前项目名为 `vocabulary-memorization`，卷名为 `vocabulary-memorization_mysql_data` 和 `vocabulary-memorization_audio_data`；迁移卷未带 Compose 标签。
- 数据和凭据留在服务器；仓库同步排除 `.env`，迁移 JSON 不复制进 Git。
- 本次是本项目通用运维配置修正，不涉及客户定制、公共业务代码、接口或数据库结构。

## 修复范围与边界

- 更新部署说明、README/贡献指南的生产入口、两个发布技能和脚本访问提示。
- 保留默认 Compose 的首次部署能力，新增显式选用的生产覆盖文件，固定项目名并将现有数据库、音频卷声明为 external；卷缺失时失败，避免误建空卷。
- 删除旧服务器专属的安全组、端口占用、ufw 和网络必然超时断言；新服务器的具体安全组规则仍未查询，不写成已确认事实。
- 同步仓库基础 Compose 与生产覆盖文件后再构建；不继续用无 build 的迁移 JSON 作为源码更新入口。
- 独立复核补充：原备份写入 MySQL 容器 `/tmp`，更换配置重建容器可能丢失备份。改为服务器 `backups/` 持久化目录，并在 Git/构建上下文中排除备份、迁移 JSON 和凭据。
- 本次只提交和推送，不升级版本、不部署、不修改服务器 `.env`、数据卷或 SSH 服务设置，不写入任何密码或私钥。

## 验收标准

1. 当前部署入口统一使用新 IP；所有 SSH 命令指定 `-p 7339`，rsync 指定 `-e 'ssh -p 7339'`，两份发布技能一致。
2. 生产配置合并后具备后端源码构建配置，项目名与两个真实数据卷名保持一致，卷为 external。
3. 服务器实测事实与待核实事项在文档中区分；首次部署使用基础配置，当前生产更新使用两份配置。
4. Shell 语法、技能校验、配置解析、SSH/rsync 只读链路检查通过；没有服务器变更或凭据进入 Git。
5. 完成独立复核，并提交推送到 `origin/main`。
