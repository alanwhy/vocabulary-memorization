# 背诵颜色配置与模糊复习

## 需求陈述

管理员需要自行配置单词背诵/出现次数的起始色、终止色和分段数，系统自动生成渐变。该颜色要同时用于次数徽标和例句中出现过的词。闪卡复习需要增加“模糊”选项，用于“先不认识、看例句后认出”的情形；其后续复习频率低于“不认识”。近义词、反义词和形近词里若含有系统词库单词，应以主题色提示。

## 定制 or 通用 ⚠️ 必填

- [x] **通用能力** —— 受益范围：本应用全部管理员和登录用户。

本仓库是单部署应用，`.claude/ai-profile.md` 未声明实际的公共层/定制层路径；本需求面向所有用户，不存在单客户定制落点。

## 核心语义与数据模型 ⚠️ 必填

- **配置键与取值** `[已确认]`：现有 `settings` 表以 `name` 为主键、`value` 为文本值，启动时通过 `SeedIfMissing` 播种，管理员保存后刷新内存缓存。新增“起始色、终止色、分段数”沿用该模型，不增加新表。
- **颜色分段含义** `[已确认]`：次数徽标目前把出现/背诵次数按 `1、3、5、7、9、11+` 映射为六档。新规则保留“每 2 次升一档”的口径：`level = min(floor((count - 1) / 2) + 1, segments)`；管理员指定的 `segments` 只决定档位数量，起始色和终止色在各档位间线性插值。缺省配置为 `#e4f7e9` 至 `#a11d1d`、6 档。
- **词库命中语义** `[已确认]`：`/api/vocabulary` 返回 `word_key → occurrence_count` 的全局索引；例句、近义词、反义词、形近词均可由此判断是否在系统中出现过。例句命中使用与次数徽标相同的渐变色；后三类命中只使用主题色。
- **闪卡评分与排期** `[已确认]`：当前评分为 `good`、`hard`、`again`，所有评分都会使 `review_count + 1`；`good` 归档，其余评分写回到期日、间隔和难度系数。新增 `fuzzy` 也不归档，统计次数同样加 1。
- **模糊的确定规则** `[已确认，用户确认]`：首次“模糊”安排为 1 天；已有间隔时按约 1.1 倍递增，难度系数减 0.10。它降低的是后续复习频率，不降低累计背诵统计；“不认识”仍重置 1 天、难度减 0.20。
- **多入口一致性** `[已确认]`：单词卡片、闪卡正面和后台词库共用次数徽标；例句存在于单词详情和闪卡；近反义/形近词的展示入口目前在闪卡背面。本次都必须使用同一份颜色规则或命中规则。

## 设计要点

1. **复用设置表和管理员设置接口**。新增三项配置到现有读写与缓存链路，避免新建配置子系统；增加登录用户可读的公开配置接口，前端页面加载时获取，管理员配置仅允许管理员修改。
2. **前端统一计算渐变与档位**。用一个纯工具把次数映射为档位、把两端十六进制色插值为每档颜色，次数徽标和例句共用它，删除写死的六档热力 CSS。
3. **命中标记按内容类型区分**。例句命中使用次数渐变，满足“颜色一致”；近义/反义/形近词只追加主题色，避免把“存在于系统”误解为其自身背诵热度。
4. **`fuzzy` 是独立评分，不复用 `hard`**。保留“看例句后认出”的语义和可读的后端规则；`good`、`hard`、`again` 旧行为不改变。
5. **被否方案**：不把颜色配置放入前端本地存储，因为管理员修改后其他用户无法同步；不把“模糊”映射为 `hard`，因为二者的间隔增长与难度下降不同。

## 边界行为清单 ⚠️ 必填

- [x] **空 / 无数据场景**：颜色接口未读到配置时使用内置默认值；词库索引为空时不高亮；无近反义/形近词时不渲染标记。
- [x] **异常状态**：管理员提交非法颜色或分段数时返回 400，不更新既有设置；前端获取颜色配置失败时保持默认颜色，不影响单词展示；未登录用户不能读取颜色配置或操作闪卡。
- [x] **历史数据 / 存储结构变更**：不新增表。已有设置缺失时启动播种默认值；旧闪卡评分记录无 `fuzzy`，按原值保持原排期数据。
- [x] **原有 mock / 测试替身 / 本地持久化状态**：扩展 `settingsStore` 的假实现和设置用例；颜色、分档和 `fuzzy` 排期通过纯函数用例覆盖。
- [x] **是否新增或变更接口（契约变更）**：新增登录用户可读的颜色配置接口；管理员设置的 GET/PUT 响应与请求增加三项非敏感字段；闪卡评分请求允许 `fuzzy`。
- [x] **权限 / 角色差异**：颜色配置写入仅管理员可用；读取限登录用户；所有登录用户看到相同的管理员配置；闪卡仍只能更新本人单词。
- [x] **并发、重复请求、幂等性**：设置写入沿用现有整组更新；快速重复点击评分沿用前端提交锁和后端按当前词状态更新，`fuzzy` 不另引入非幂等副作用。
