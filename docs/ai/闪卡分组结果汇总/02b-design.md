# 闪卡分组结果前端设计

## 前端详细设计

### 页面与状态

`FlashcardView` 沿用加载、今日完成、本组完成、当前卡片分支。在本组完成分支内展示标题、实际组数/累计数、三列统计和两个分类列表，底部保留“再来一组”。没有当前卡片且首次加载失败时显示重试。

`useFlashcardQueue` 新增模块级 `groupResults = ref([])`，每项结构为 `{ word: <本组单词对象>, rating: 'again' | 'fuzzy' | 'good' }`。`groupCounts` 从记录计算 `{ again, fuzzy, good }`；导出供页面消费。

`rate` 在请求前捕获当前单词对象，请求成功后增加本组记录、累计数量，沿用翻面延迟再推进索引。`loadQueue` 在成功取得队列后清空结果，失败保持全部旧状态；加载与评分共用互斥判断，避免旧请求写入新组。

页面计算 `resultGroups`：只包含 `again` 与 `fuzzy`，各组从本组记录按顺序筛选。每词派生展示单词、首个非空音标、全部非空释义（分号连接），保留 `id` 用作列表 key、`word_key` 用于播放。没有任何额外学习内容或编辑交互。

### 展示与交互

- 三类统计显示“不认识、模糊、认识”；不认识用危险色、模糊用警示色、认识用成功色，复用现有主题变量。
- 列表每行先单词与音标/喇叭，再中文释义；释义与长单词自动换行，分类为零显示“本组没有……的单词”。
- 错误提示移到状态分支外，下一组失败时仍能看到并重试。
- 当前卡片变为 `null` 时已有 watcher 不播放音频，结果列表仅点击喇叭时朗读。
- 下一组为空后沿用今日完成页面；不提前探测余量、不自动跳过结果。
