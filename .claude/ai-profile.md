# 项目声明模板

> **用法**：四个入口 skill 首次运行时会自动把这份文件拷到业务仓库的 `.claude/ai-profile.md`，不需要手动拷贝。
>
> **公共层路径 / 定制层路径**：skill 会按 [`layer-detect.md`](layer-detect.md) 自动识别候选并请你确认——多个公共层不需要自己一条条写，看候选打勾/补漏即可。仅当你在纯网页版/无 codegraph 环境手动使用本模板时，才需要照下面的示例自己填。
>
> 其余字段（测试命令、备注）目前仍需手填，约 2-3 分钟。字段留空有明确的降级行为，不会导致 skill 报错，但会削弱对应检查的效果。

---

## 公共层路径

被多个客户 / 多个项目复用的代码目录。改动落在这里时，`/sw-review` 会要求书面说明理由。

```
src/components/common/
src/utils/
src/api/base/
packages/shared/
```

**留空的后果**：退化为 `codegraph impact` 启发式 —— 影响面跨越多个模块时警示。只警示不阻塞，误报率较高。

**为什么值得填**：多客户二次开发里最大的风险是「给 A 客户加需求时改了公共代码」，今天满足 A，下个月 B 客户升级时出问题。这类缺陷 diff 看起来小而合理，人工 review 容易漏。

## 定制层路径

单客户定制代码所在目录。改动落在这里时不要求写测试（变更频繁，测试寿命短于代码）。

```
src/views/customer-a/
src/pages/tenant/
src/config/customers/
```

**留空的后果**：无法确认改动是否落在正确的层，第 8 节的污染检查只能靠启发式。

## 测试命令

**能真实跑测试的那一条命令**。没有就写「无」，不要写脚手架自带的假命令。

```
无
```

或

```
npx jest --passWithNoTests=false
```

**注意**：`package.json` 里的 `"test": "vite --mode test"` 不是测试命令，它会启动 dev server 并挂住。填写前先自己跑一遍确认。

**留空或填「无」的后果**：`/sw-impl` 对所有改动都走「验证前置」模式，不要求写测试。这是本团队的默认状态，不是异常。
